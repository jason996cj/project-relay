# 项目接力

让下一次接手的 AI 不依赖旧聊天记录，也能知道项目做到了哪里、哪些结果可信、接下来该做什么。

## 项目记录

在项目根目录维护 `PROJECT_STATE.md`。已有同类进度文档时直接复用，不另建重复记录。

记录应简短、具体，详细代码、数据和日志留在原位置，文档中只写必要说明与路径。路径尽量相对项目根目录，方便不同工具读取。

## 接手时

1. 先读项目记录，了解目标、当前方法、已有成果和下一步。
2. 核对下一步直接涉及的数据、代码和结果，不重新扫描全部历史。
3. 沿用已有工作继续推进。只有发现相关输入或方法变化、结果缺失或验证失败时，才重做受影响的部分。
4. 记录与实际文件不一致时，说明差异并核实；无法确认的内容标为“待核实”，不要猜测。

## 何时更新

只在以下时机更新记录：

- 关键数据、预处理、算法或重要参数发生变化。
- 完成一个有明确产物的阶段。
- 出现影响后续工作的失败或阻塞。
- 用户要求交接，或本次工作准备结束。

不要逐条记录工具调用，也不要把聊天过程搬进项目文档。

## 记录什么

- **数据**：使用了什么数据、放在哪里、版本或范围，以及影响结果的重要处理。
- **算法**：当前方法、代码入口和关键参数；重要变化写清“改了什么、为什么改、影响哪些结果”。
- **成果**：产物位置、对应的数据与方法、实际验证结果。明确区分已验证、未验证和未通过。
- **下一步**：从哪里继续、具体做什么、如何判断完成；必要时附运行命令和环境要求。

保留仍影响后续工作的关键决定和失败原因。方法改变后，明确哪些旧结果已经失效或需要重算。

## 项目记录模板

按项目需要填写，不适用的字段可删除，不必为了填满模板增加工作。

```markdown
# 项目状态

更新时间：

## 目标与当前阶段
- 项目目标：
- 当前做到：

## 当前数据与方法
- 数据位置、版本或范围：
- 关键预处理：
- 方法与代码入口：
- 重要参数：
- 运行命令与必要环境：

## 关键变化
- 日期：改了什么；为什么改；影响哪些结果。

## 阶段性成果
- 成果及文件位置：
- 对应的数据与方法版本：
- 已完成的验证及结果：
- 未验证、未通过或需要重算的部分：

## 下一步
- 接下来做：
- 所需输入或前置条件：
- 完成判据：
- 当前阻塞或待确认问题：
```

## 交接时

更新项目记录后，简要告诉用户：

- 本次完成了什么。
- 项目记录和成果在哪里。
- 下一位接手者应从哪一步开始。

交接所需信息应保存在项目文件中，不只留在当前聊天里。
